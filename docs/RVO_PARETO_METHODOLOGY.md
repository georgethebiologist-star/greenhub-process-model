# GreenHub RVO Pareto analysis methodology

## Reproducing the analysis

From the model repository root, run:

```powershell
$env:GREENHUB_PARETO_DESIGNS='16'
$env:GREENHUB_PARETO_WORKERS='1'
.\.venv\Scripts\python.exe scripts\run_rvo_pareto_analysis.py
.\.venv\Scripts\python.exe scripts\append_rvo_baseline_references.py
.\.venv\Scripts\python.exe scripts\generate_rvo_pareto_pngs.py
.\.venv\Scripts\python.exe scripts\verify_pareto_replay.py
```

The runner explicitly sets `feed_preparation=F1` in every request. It creates separate paired batches for active protein recovery (PR1–PR3) and protein bypass (PR0). Each sampled process design is evaluated once, then paired with 24 post-route finance overlays: four hypothetical CAPEX-grant levels (0%, 30%, 45%, 60%) crossed with grass-utilization bonuses of €0, 10, 20, 30, 40 and 50 per wet tonne processed. The default is 16 process designs per protein group, evaluated serially. A single process simulation is paired with the 24 finance cases; those overlays do not rerun or alter process chemistry. This bounded design explores up to 768 UI configurations before product-gate exclusions, rather than running 2,000 full process simulations. The UI's shared economic defaults are read from `Greenhub/data/greenhub_economic_defaults.json`. Seed, configurations, raw model outputs, selected candidates, objectives, warnings and limitations are retained in `Greenhub/results/pareto_rvo_2026/`.

When a scenario does not supply an explicit `feed_composition`, the runner pins all 74 fractions from `Greenhub/data/Pre-treatment/Feedstock/greenhub_feed_composition_defaults.json` into the saved configuration. Explicit scenario values have priority. The manifest records the profile ID and SHA-256 so that candidate replay is not silently changed by a future default-profile edit.

## Sampling and optimization

**Publication status (2026-11-06):** the published preview uses monthly seasonal scheduling and contains 1,680 selectable input configurations (1,008 protein-enabled; 672 bypass), from 70 product-eligible physical route/schedule designs with 24 finance overlays each. Twenty productless bypass designs were rejected. Every selectable catalog item contains its exact runnable process request, evidence classes, and monthly available/collected/released/processed/uncollected/inventory series. The catalog is rebuilt from the same evaluated rows as the published front.

The published batch was checked against the current decision-support service for 19 varied saved configurations (including finance, LCA, products, utilities and balance outputs), then through the live HTTP API for four configurations spanning both protein groups and multiple support cases. In the local app, Vite proxies `/api/v1` to `GREENHUB_BACKEND_URL` (default `http://127.0.0.1:8000`); the local app must be restarted after backend source changes so saved scenarios use the current calculation code. Clicking a candidate sends its input configuration only. Support-inclusive NPV and NPV without public support are both reported; the latter still includes the separate grass logistics bonus. Product-sales margin and operating profit including the grass bonus are reported separately. Public grants and biomethane support are excluded from operating profit. This is a screening comparison, not a grant award or investment decision.

The runner now cycles through four explicit mowing-calendar scenarios: one cut in late summer; one cut in late autumn; two cuts in June and late summer; and two cuts in June and late autumn. The one-cut cases use the published Zeeland one-cut technical potential (25,300 t fresh/y); the two-cut cases use the published future 100%-collection technical potential (42,300 t/y, with 25,300 t in the broad summer period and 17,000 t in the broad autumn period). These are class-B regional technical estimates, not measured plant supply, current contracts, or a national default. Neither source specifies monthly delivered supply. Where the report gives broad summer/autumn totals, each is allocated across its stated months by calendar-day weights; the one-cut annual potential is evenly allocated across the named experimental mowing window. These monthly profiles are class-C assumptions informed by the VITO/MooV report and Dutch roadside mowing-window study ([Bakker et al., 2026, DOI 10.1111/avsc.70085](https://doi.org/10.1111/avsc.70085)), not measured monthly biomass curves. Each saved request contains its own annual total, monthly availability vector, season bounds, evidence classes, and limitation text. The source table is `Greenhub/data/Pre-treatment/Feedstock/zeeland_availability_scenarios.csv`; the runtime default and Configure overrides are unchanged.

The design space samples plant feed rate over the configured range, then calculates annual throughput against the saved monthly supply schedule rather than assuming 8,760 h/y. Each request uses the applicable one-cut or two-cut published technical potential, a 14-day processing delay, and a monthly timestep; the target cap uses the same backend operating-calendar resolver as the simulation, including the delayed processing tail. Requested feed target and actually processed feed are reported separately. Any shortfall or ending inventory from monthly resolution/equipment capacity is retained and exposed rather than treated as delivered product throughput. The seasonal cases run June–August, September–November, or June–November, depending on the mowing schedule. The 10-site 2023 standing-biomass data are available at [Zenodo DOI 10.5281/zenodo.15349657](https://doi.org/10.5281/zenodo.15349657), but are not converted into annual collected supply. The monthly timestep keeps the serial process batch tractable; the exact saved timestep, monthly profile, route IDs, feed composition, and finance assumptions are replayed by the UI. Active process routes are sampled from AD0/AD1/AD3, BG0/BG2/BG3/BG4, NR0/NR1/NR2/NR3/NR4/NR6/NR7, protein routes PR1–PR3 or PR0, and process order A–C where allowed. Original modeled sales and partial OPEX are used unchanged. No assumed labour, logistics or energy reductions and no protein-yield or nutrient-recovery revenue uplifts are sampled or applied. Legacy improvement settings are ignored. Product-sales margin is product sales minus partial OPEX; operating profit adds the separately displayed grass logistics bonus but excludes public grants/biomethane support. NPV is after-tax screening cash flow including the bonus and explicitly hypothetical public-support cash inflows. PEF is excluded. Each design is run through BioSTEAM once; its same process, TEA and LCA result is paired with 24 recalculated finance overlays, so support cases cannot change physical outputs.

For each protein group, nondominated fronts are calculated for (1) net carbon minimized and NPV maximized, (2) present value of assumed support minimized and NPV maximized, and (3) all three objectives simultaneously. Separate net-carbon/NPV fronts are also calculated for each of the 24 grant × grass-bonus combinations. A fixed-process grass-bonus sensitivity compares the six bonus values without changing process configuration. Nondominance is bounded to the saved random sample and does not imply a global optimum. Numerically complete rows are retained even when technical evidence gates are conditional; gate status and rejection reasons remain attached to each row. Negative operating margins and dominated rows are retained in the underlying batch.

Up to 25 representatives are selected from each combined or two-objective front and from each of the 24 support-case fronts; actual counts can be lower when the nondominated set is smaller. A separate deterministic scenario catalog takes up to 42 product-eligible process designs per support case and protein route, balanced across the sample. With 16 designs per group the UI can expose up to 768 route × support combinations before product-gate exclusions. These are sampled configurations, not all Pareto-front members. Candidate labels use `Protein–Biogas–N–P–K`; `X` indicates bypass. In the website and figures, nondominated points and selected endpoints are highlighted.

Pareto eligibility requires at least one positive annual flow (>1e-9 in the reported model basis) among dry protein, biostimulant, biomethane, phosphorus, ammonium, potassium concentrate, or nutrient-rich solids. Productless cases remain in the saved batch as rejected records with an explicit reason; they are excluded from all fronts and selected-candidate lists. This is an output gate, not a claim that the remaining products meet commercial quality specifications.

## Financial support cases

These are user-defined what-if assumptions, not RVO awards or verified tariffs. CAPEX grant levels remain an independent scenario dimension. Biomethane value and the grass-use bonus are separate annual support overlays:

| Case | Hypothetical upfront CAPEX grant | Biomethane value proxy | Grass utilization/logistics bonus |
|---|---:|---:|---|
| C30 | 30% | €1.87/Nm³ modeled biomethane for 15 y | €0–50/wet t for 20 y |
| C45 | 45% | €1.87/Nm³ modeled biomethane for 15 y | €0–50/wet t for 20 y |
| C60 | 60% | €1.87/Nm³ modeled biomethane for 15 y | €0–50/wet t for 20 y |
| C0 | 0% | €1.87/Nm³ modeled biomethane for 15 y | €0–50/wet t for 20 y |

The DEI+ official programme page describes project categories and maximum grant amounts but does not establish the user-supplied percentages as generally applicable rates. SDE++ renewable-gas support is tied to qualifying grid injection and corrected market prices; a generic €/t feed proxy is not the official tariff calculation. These runs do not check eligibility, award probability, cost ceilings, market corrections, or co-funding. See [RVO DEI+ circular economy](https://www.rvo.nl/subsidies-financiering/dei/circulaire-economie-en-grootschalige-biobased-projecten), [RVO renewable gas SDE++](https://english.rvo.nl/subsidies-financing/sde/aanvragen/renewable-gas), and [RVO SDE++ features](https://english.rvo.nl/subsidies-financing/sde/features).

The annual biomethane-value public-support proxy is calculated from each candidate’s modeled biomethane mass divided by 0.71751 kg/Nm³, the traceable pure-methane reference density at 0°C and 101.325 kPa, multiplied by €1.87/Nm³. The grass-use bonus is rate × annual wet tonnes actually processed; it is modeled as user-defined logistics operating income, shown separately from product sales and public support, and does not change process outputs, chemistry, or emissions. C0 has zero CAPEX grant but may still receive the biomethane public-support assumption. Neither value is verified programme income or awarded support. An additional NPV field excluding both public support and the grass bonus is available for comparisons that should remove both assumptions.

`scripts/verify_pareto_replay.py` replays five NPV strata (minimum, 25th percentile, median, 75th percentile, maximum) for both protein-route groups at each of the six C0 grass-bonus rates, plus the same strata for C60-GB50. It compares revenue, OPEX, direct CAPEX, public-support present value, NPV, IRR, and payback against the saved batch using `DecisionSupportService`, the evaluator used by the UI. This is an internal consistency check, not independent validation of the financial assumptions.

NPV uses the same post-route TEA calculation as standalone Configure: annual modeled product sales, annual OPEX, high direct CAPEX screening basis, tax rate 25.8%, 20-year life, 8% discount rate, and finite assumptions (15 years for the biomethane public-support proxy, 20 years for the grass logistics bonus). NPV includes explicitly assumed CAPEX-grant and public operating-support cash inflows; it is not operating profit. Product-sales margin is sales minus partial OPEX. Operating profit adds the grass logistics bonus to that margin but excludes public support, tax and capital recovery. The UI shows product sales, the grass logistics bonus, public operating support, and CAPEX grant as separate chart series, plus cumulative project cash flow including public support. Each cash flow is counted once. Annual capital recovery is not deducted again from NPV cash flows. If product revenue is incomplete, investment KPIs including NPV/IRR/payback remain blocked rather than treating missing prices as zero.

The UI's selected-point action replays the exact saved process request and its finance assumptions through the same backend TEA evaluator; only the run ID changes. Cost overlays are idempotent; paired support cases do not add labor or utility costs a second time. Grass-bonus duration and biomethane-bonus duration are stored/restored independently; `opex_support_years` is a legacy shared-duration fallback only when the specific biomethane duration is absent. To regenerate the sampled process designs, run `python scripts/run_rvo_pareto_analysis.py` serially, then the PNG generator. Full records are split into per-group sample shards below 70 MiB; `latest.json`, `rvo_pareto_manifest.json`, and `latest_ui.json` are compact indexes/catalogs under 100 MiB. `Greenhub.pareto_reporting.load_pareto_results` reassembles legacy monolithic or sharded results for reports and analysis.

NPV remains a screening proxy, not investment-grade TEA. It uses a high-direct-CAPEX basis where installed equipment costs are unavailable and excludes financing, escalation, replacement CAPEX, working capital, residual value and unverified grant eligibility. Results inherit any incomplete source cost or product-price assumptions shown with the candidate.

## Climate and carbon objectives

The inventory includes modeled process energy and vented process emissions. Electricity uses the JRC Netherlands life-cycle electricity factor of 0.406463 kg CO2e/kWh (2021, Table3_EU_LC), including upstream electricity supply-chain emissions; the source is [JRC dataset DOI 10.2905/JRC.4800KC0](https://doi.org/10.2905/JRC.4800KC0). Heat uses the supplied Dutch average 30.96 kg CO2e/GJ converted to 0.111456 kg CO2e/kWh. Other upstream materials, equipment, transport, feedstock production and downstream burdens are excluded; exclusion is not a zero-burden claim. The electricity factor is a national 2021 life-cycle value, not a supplier-specific current-year factor. Net carbon and LCA completeness must not be conflated.

`net_carbon` is defined as operational climate load converted to elemental carbon equivalent (`t CO2e × 12/44`) minus retained product carbon. It credits 100% of modeled press-cake carbon to furniture and 10% of nutrient-rich-solids carbon as retained in soil. Protein carbon receives no storage credit because its feed/biostimulant fate is unresolved. Furniture manufacturing loss and end-of-life release are not included. Thus this is a screening proxy for a mixed operational burden and assumed carbon stocks; it is not a complete LCA climate impact or a durable-removal claim.

The support overlay converts modeled biomethane product mass (kg/year) to Nm³/year using 0.71751 kg/Nm³ for pure methane at 273.15 K and 101.325 kPa, from [NIST NBS IR 85-3028, Section 1.2](https://nvlpubs.nist.gov/nistpubs/Legacy/IR/nbsir85-3028.pdf). The value and uncertainty/provenance metadata are also stored in `Greenhub/data/greenhub_economic_defaults.json`. UI replay applies the same conversion from the exact run's product mass, so the €/Nm³ support basis and Pareto/UI NPV calculations match. The separate `volumetric_products.biomethane` result remains model-condition m³ and is not substituted for Nm³ in the support calculation. Pure-methane density is a screening normalization; actual biomethane composition and specification remain unverified.

## Figures and quality checks

The PNG generator uses the existing GreenHub report palette and records figure, source batch, scenario, units and file path in `results/report_figures/rvo_pareto_figure_index.csv`. It creates two-objective fronts, 3D three-objective fronts, selected-candidate comparison plots and per-candidate product, utility and KPI summaries in `08_candidate_comparison/`. Run visual inspection on the exported images before publication; numerical model warnings and incomplete evidence are retained in output metadata, not drawn over the figures.

The web chart reads the latest analysis through `/api/v1/decision-support/pareto/latest`. A freshly started API serves `Greenhub/results/pareto_rvo_2026/latest_ui.json`, and the offline preview uses `frontend/public/data/greenhub-pareto-latest.json`; both are published from the same bounded projection and contain the same selectable scenario catalog without the full evaluated-sample ledger. The UI exposes CAPEX-grant and grass-logistics-bonus filters and supports both plotted-point selection and a scenario selector. Clicking “Run this scenario in Results” submits the saved process input configuration—not the result payload—and uses the same route IDs, seasonal availability, throughput, timestep, feed composition, and storage conditions that were used by Pareto. Productless scenarios are excluded before display. Full route-specific records are retained in bounded batch/sample shards. A fully interactive 3D view is not implemented; the static 3D PNG is the three-objective visualization.
