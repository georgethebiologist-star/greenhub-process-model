# GreenHub input data management and FAIR catalog

## Purpose and authority

`Greenhub/data/fair_input_catalog/master_input_catalog.csv` and `.json` are generated indexes of the inputs and evidence files under `Greenhub/data/`. The catalog records file checksum, repository path, role, links to matching source registers, and known dataset readiness. It is an index, not a shadow parameter store: editing the catalog does not change a simulation. Rebuild it with:

```powershell
.\.venv\Scripts\python.exe scripts\build_fair_input_catalog.py
```

The master workbook `Greenhub/data/greenhub_feed_inputs.xlsx` now has additive `FAIR_Catalog` and `Master_Inputs` sheets. The latter is a normalized, read-only snapshot of canonical parameters, feed compounds, economic defaults and prices, TEA cost records, LCA factors, and the opt-in storage-reaction package. Both are browsable snapshots, not new precedence layers. Existing named sheets, sheet names, and control values are preserved; the ReadMe's quality-class definitions were aligned with the current UI, and existing loaders remain unchanged.

## Existing runtime input and override flow

- Grass component defaults shown in the UI come from `Greenhub/data/Pre-treatment/Feedstock/greenhub_feed_composition_defaults.json`; the UI sends normalized component fractions in the process request. Per-component source classes and assumptions are kept with each component.
- Frontend-only offline/initial preview references are held in `Greenhub/data/frontend/preview_parameter_defaults.json` and labeled in the UI as planning references, not applied to backend runs. They are cataloged for traceability but cannot override the canonical parameter registry, workbook controls, `SimulationRequest`, or user-provided feed composition. The VARTA grass-moisture preview uses 0.857 wet-basis water (14.3% measured dry matter); the formerly stale 0.78 value is removed.
- Workbook sheets remain loaded by their existing named-sheet loaders. `ModelControl` controls and selected sample IDs apply only through the existing workbook-backed feedstock path; they do not silently replace the UI's explicit component request.
- `SimulationRequest` carries process selections, schedules, explicit feed composition and design overrides. `ParameterService` resolves canonical values and explicit parameter overrides through the current registry. The catalog does not alter this order.
- Configure > Economics values are passed in `candidate_economics` / `financial_assumptions` to post-route TEA and LCA. These are report overlays: they do not modify process chemistry, scenario IDs, component or energy balances, or process outputs.
- Reports and exports use the run request and post-route analysis associated with that run. Editing inputs marks the displayed result stale until a new run is completed.

## Evidence classes and missingness

Evidence and missingness are separate. A = measured project data; B = directly reported literature, official, or supplier evidence; C = a literature-linked assumption or proxy; D is a deprecated legacy label for unsupported assumptions. In normalized catalogs, legacy D/E inputs are labeled E (unverified/placeholder); this is a taxonomy mapping, not an evidence upgrade. The frontend status fallback now maps measured to A, literature-default/calibrated to B, explicitly literature-linked assumptions to C, and all other/override/placeholder states to E; unsupported legacy D is normalized to E for display. Legacy API payloads may still contain D and remain accepted for compatibility. A DOI by itself does not establish applicability. B does not mean high transferability: source fit, geography, scale, year, grade, and cost boundary remain separately reported. An unknown is not zero; structural zero assumptions are not measurements of absence.

For mass-composition records, `quality_class` and `value_status` are separate. A/B/C are used only when the value has a defensible evidence grade; `value_status` distinguishes measured, literature-derived, unmeasured numeric compatibility fallback, calculated residual, and structural initial state. Unsupported values retain their numeric compatibility fallback where required, but are visibly labeled M/R/S in the feed editor rather than passed off as evidence. This does not resolve the measurement gap.

The active grass profile contains 74 records: 2 class A, 0 class B, 18 class C, 49 unmeasured numeric fallbacks, one calculated profile-closure residual, and four structural/model-state initializations. It has no D-class component rows. The UI distinguishes evidence grades from M (unmeasured numeric fallback), R (calculated baseline closure residual), and S (structural state at the raw-feed boundary). Sixteen M fields have nonzero compatibility values and remain active in the reset run; 33 M fields are zero. Neither is a measured presence/absence result. R is the exact residual needed to close the stored baseline, not a measured or separately identified chemical fraction. M/R/S status metadata does not turn these rows into evidence grades. Class C values are literature-linked assumptions, not direct measurements of every chemical species. The UI soluble/suspended-protein split is a class-C 22.8/77.2 allocation derived from Hoekstra ryegrass nitrogen fractions and Smit roadside-grass total protein; it is not a GreenHub protein-form assay.

The 16 nonzero M fields map to open acquisition requirements as follows:

REQ-GH-P3-10 remains open for the zero-valued species-level sugar and organic-acid fields. The ParticulateBiodegradableOrganics closure residual remains an R-status bookkeeping value. It is not another measurement or a literature-backed composition input.

The Dutch roadside-grass report includes the ten-site 2023 standing-biomass summary from Bakker et al. (2026), converted from g DM/m² to t DM/ha. The dataset DOI is unresolved: the article cites `10.5281/zenodo.15349657`, while the Wageningen research portal lists `10.5281/zenodo.15349656`. This metadata conflict is preserved in the source register and sidecars; do not treat the Zenodo license or identifier as confirmed until checked with the repository/authors. The schedule reporter exposes the mean and observed range as a class-B literature reference. It does not replace the annual wet-tonne availability input, because standing biomass is not annual harvested yield or delivered feed.

The default lifecycle electricity factor uses the JRC Netherlands 2021 life-cycle value (0.406463 t CO₂e/MWh = 0.406463 kg CO₂e/kWh), with upstream electricity supply included. The source workbook, table/cell context, conversion, date, geography, applicability, uncertainty, DOI, and CC BY 4.0 license are recorded in `Greenhub/data/lca/source_data/`. The staged isoelectric-recovery dataset has record-level metadata in `Greenhub/data/Protein recovery/Isoelectric/recovery_metadata.json`. REC-004's DOI was corrected to `10.1016/j.biteb.2022.101190`. REC-001 may be selected as a literature candidate (class B, proxy transferability), but it measures total nitrogen recovery from grass-clover rather than recovery of the model's soluble-protein pool. REC-002/003 also include nitrogen in fiber and are not precipitation-efficiency measurements. These basis mismatches are explicit; four zero-valued structural/model-state records display as S, not as evidence classes. The literature evidence does not validate a direct roadside-grass precipitation model.

### Additional direct operating evidence (2026-11-05)

`Greenhub/data/Pre-treatment/Mechanical/literature_operating_candidates.csv` adds four directly reported, DOI-linked candidates: fresh timothy single-screw liquid yield (0.301 kg liquid/kg fresh sample) and grass-silage digestion setpoints (35 °C, 30 d HRT, 2 kg VS/m³/d OLR). They are class B as literature measurements, but `proxy_high` transferability and explicit limitations remain visible. The press study used fertilised Finnish timothy, added 0.4 L water/kg fresh grass during two press cycles, and did not unambiguously separate that water from the reported liquid-yield basis. The digestion study later reports instability at the initial 35 °C / 30 d / 2 kg VS/m³/d conditions. These candidates are selectable only in `literature_default` or `expert_override` mode; default workbook values and structural-mode baseline remain unchanged. Do not interpret them as validated Dutch roadside-grass operating optima.

## FAIR status and limitations

### Biomethane price provenance correction (2026-11-05)

The UI's selected biomethane price remains the user's supplied €0.88/m³ assumption (quality C in the current benchmark register); it is not a directly quoted market value. Its record is linked to the supplied Dutch gas-price page and retains the supplied unit. Separately, the ACER 2025 waste-derived biomethane TTF+GO benchmark is recorded as €60.51/MWh (quality B), with a €49.87–75.10/MWh reported range and source location Slide 27, [ACER data item 1226](https://aegis.acer.europa.eu/chest/dataitems/1226/view). This is a market benchmark, not a direct €/m³ replacement or proof that the product grades are equivalent. The frontend labels the selected assumption and benchmark separately.

Historical snapshot, superseded by the 2026-11-11 normalization below: the earlier generated master-input catalog exposed legacy D labels. That snapshot did not change model defaults or numeric inputs. Unknowns were not filled with zero. Current normalized exports map unsupported legacy D/E assignments to E, which means unverified/unsupported—not literature evidence—and use blank values where none exists.

### Feed-profile source link behavior

The feed profile stores literature links under `source_url`, while the older feed editor expected `url`; DOI text could appear without a clickable link. The editor now resolves `url`, `source_url`, or DOI URL and renders a compact source link on the corresponding feed row. This is presentation-only: composition amounts, evidence classes, override values, reset-to-default behavior, normalization, and run payload are unchanged. Frontend lint and the decision-support rendering/evidence/request-payload checks pass with a regression assertion for the field-name mapping.

Historical Phase 3–7 classification snapshot, superseded by the 2026-11-11 catalog rebuild: legacy unsupported values were previously displayed as D. The current canonical parameter registry still has 547 rows: 10 B-class Phase 6 scrubber/recycle entries, 528 E-source placeholders, seven project controls, and two blank values. The separate Phase 3–7 runtime reuse catalog contains 538 records: 528 E and 10 B, with no D assignments. A citation attached to a broader or related measurement is still not enough to promote a model partition or placeholder.

### VARTA feed selection boundary

The backend option list advertises `grass_varta_default`, and `load_roadside_grass_specification()` can resolve that sample into VARTA total solids and wet-basis N/P/K aggregates. The current Run Simulation UI instead submits the explicit 74-component profile from `greenhub_feed_composition_defaults.json`; its quasi-dynamic request also submits `biomass_schedule`. In `SimulationService`, a supplied `biomass_schedule` bypasses `feed_supply_profile_id`, and the explicit `feed_composition` takes precedence over the model's workbook feed. Therefore, VARTA's separately measured N/P/K aggregates are available in the workbook-backed feed path but are not currently selected as those aggregates by the main explicit-composition UI run. Do not imply that the VARTA N/P/K measurements are independently active in the 74-component composition: the profile contains derived/assumed molecular allocations. Exposing a selectable feed profile while preserving exact override precedence requires a deliberate end-to-end request-to-report change and is still an integration gap.

### VARTA sample profiles normalized for reuse (2026-11-10)

Three project-supplied samples now also have records conforming to the platform material-profile schema: GreenHub whole grass, Reterra road-verge grass N36, and a separately reported GreenHub grass-juice sample. The profiles are in `biorefinery_platform/examples/material_profiles/`. Each carries the original sample/worksheet row, units, sample basis, local source ID, rights status, and missing metadata. Total N/P/K and other nutrient assays remain analytical properties, not mutually exclusive mass fractions; no speciation, juice yield, feed/juice pairing, or closure is inferred. The Reterra crude-protein results are recorded only for that distinct sample and do not replace the current GreenHub UI default. The juice concentrations are not converted into process flows because volume, density, and matched parent feed are absent. These records improve discovery and cross-project reuse but are not additional runtime inputs or D4 promotions.

### UI feed-composition evidence review (2026-11-09)

The feed editor exposes the full profile to the run request; every numeric value remains a calculation input and no API payload or default precedence has changed. The 2026-11-11 metadata correction leaves the 74-record composition values intact but reclassifies cellulose, hemicellulose, and ADL-derived lignin as C at the GreenHub profile level (the underlying source measurements remain B). The profile therefore has A=2, B=0, C=18, 49 M numeric fallbacks, 1 R closure residual, and 4 S structural/model-state records. The 70 editable UI fields account for A=2, B=0, C=18, M=49, and R=1. The two protein-product structural zeros and two internal process-state records are outside the editable UI list. The 16 nonzero fallbacks remain numerically active and explicitly unmeasured; they were not converted into literature estimates. Reference-only ryegrass free-amino-acid and nitrogen-fraction observations do not directly match GreenHub whole roadside grass. Plant-part proportions, assay-to-mass conversion, and overlap with total-N-derived protein remain unresolved; Phase 3 request `REQ-GH-P3-07` calls for matched feed, juice and cake assays with an explicit conversion method.

The local VARTA whole-grass sample remains the only A-class composition row tied to the current GreenHub batch. It reports 14.3% dry matter and total N, S, P, K, Ca, Mg, Na, chloride and trace elements; crude protein is unreported. The analytical reference panel displays those results, but only the moisture default is active in the current profile. The total elements are not mapped to ammonium, organic/particulate N, phosphate, or dissolved/particulate K because species fractions were not measured.

Additional comparators do not justify changing the active profile. Brown et al. (2020, DOI `10.1016/j.biombioe.2020.105570`, Table 3) report proximate/ultimate and theoretical methane-potential data for fresh and ensiled Lincolnshire road-verge grass. Czubaszek et al. (2024, DOI `10.3390/en17071751`, Tables 1 and 8) report seasonal fresh/ensiled roadside-grass TS, VS, TKN, P, K, Na, TOC and summed FAMEs from three replicates; FAMEs are not equivalent to crude fat/ether extract and aggregate elements do not establish chemical species. Della Rosa et al. (2022, DOI `10.1093/jas/skac223`, Table 1) report fresh cultivated ryegrass proximate/fiber and mineral comparators, but not the GreenHub batch. Varriale et al. (2024, DOI `10.1007/s00253-024-13224-0`, Table 1) report sugar, protein, amino-acid and ion concentrations in twice-centrifuged, filtered perennial-ryegrass press-juice; this is stored as a separate B/reference-only material-state dataset and is not raw-grass composition. Grassification D1.4.1 reports a Belgian ensiled roadside-grass pilot with crude protein, crude fat, carbohydrates, dry matter and nutrient values, but several bases are unspecified and its ammonium-N SD is anomalous. These sources guide acquisition and support comparison, but do not provide a defensible mapping for the GreenHub batch's protein forms, nutrient species, inert solids, foreign matter, or contaminant fractions.

### Anaerobic-digestion data addition (2026-11-10)

Maus et al. (2020, DOI `10.1186/s40793-020-00354-x`, Fig. 2 and Methods) is now transcribed into a 33-row reference table with a schema-separated perennial-ryegrass-silage material profile. It supplies measured feed analytical properties and selected two-stage/two-phase reactor settings and gas/VFA/ammonium observations, including mesophilic 37 °C and thermophilic 55 °C results. The authors' `L_N/kg VS` basis is retained; reported ± spreads are not relabeled as SD; methane, biogas, stage-specific gas fractions, and batch BMP stay separate. The source's 500 g/1500 g loading labels are preserved as batch masses, not converted to normalized OLR because the required feed interval and exact denominator are not stated. This is B-class peer-reviewed evidence for its own ryegrass silage and biofilm reactor context, not GreenHub fresh roadside grass, the active single-stage CSTR, or a basis for promoting runtime hydrolysis/conversion/inhibition defaults. The reusable material profile has no exclusive mass composition or closure claim and remains `reference_only`.

### Green-biorefinery grass-whey BMP comparator (2026-11-10)

Ravindran et al. (2022, DOI `10.3390/cleantechnol4010003`, Table 3) is now available through the dynamic evidence adapter as a named, optional Phase 5 scenario proxy. The recorded methane potential is 544.6 L CH4/kg VS (0.5446 m3 CH4/kg VS after exact litre-to-cubic-metre conversion only). The source reports grass whey from cultivated perennial ryegrass and describes a two-fold wash-water dilution; its process and substrate differ from GreenHub's isoelectric supernatant. The extracted table does not state a gas reference condition, so no Nm3 conversion is asserted. The candidate is selected only through the existing report-only closure-policy selector, remains blocked as a continuous-digester prediction (`AD_kinetics_not_implemented`), and does not change the default de-FOS-whey proxy, empirical chemistry, route, or result contracts. Roadside-grass continuous-digestion evidence from Chopda et al. (2026, DOI `10.1007/s12649-025-03274-4`) remains reference-only because the accessible abstract does not define the fresh-matter denominator or methane fraction and provides no reactor operating conditions.

Four explicit Phase 3 measurements were added to the acquisition register: batch-matched proximate/fiber composition; protein forms and free amino acids; N/P/K speciation; and a paired foreign-material/contaminant panel. The register remains a list of measurements to collect, not synthetic data. The concise companion workbook is `outputs/019fb031-1e4e-70f1-ba3b-498e77233c06/phase_3_to_7_measurement_acquisition.xlsx`.

- Findable: the catalog has a stable catalog identifier, content-addressed asset identifiers, file paths, hashes, source IDs, DOI fields and URLs. Asset identifiers are repository-local content identifiers, not registered DOIs. No DOI is fabricated. To mint externally persistent identifiers, archive a release in an appropriate repository (e.g., Zenodo) and record the resulting DOI.
- Accessible: CSV and JSON catalog formats are open and retrievable in the public repository over HTTPS; the original sources remain at their source-specific locations where linked.
- Interoperable: UTF-8 CSV/JSON, explicit SI/financial units where source files provide them, common DOI/URL identifiers, and stable column names support programmatic reuse. Unit/basis gaps are flagged as record-specific rather than inferred.
- Reusable: checksums, repository-relative provenance, runtime role, source-register linkage, DOI/URL, rights warning, and override notes are included. Rights are intentionally marked “not inferred”; the repository license does not automatically relicense third-party sources.

At the 2026-11-11 catalog build, there are 865 input assets and 923 normalized input records; 622 assets have a detected source-register or adjacent local metadata link, 490 contain a DOI-like identifier, and 251 have no source-register link. These counts overlap because some assets have DOI metadata without a register linkage. Transient Office lock files are excluded; retained phase workbooks are indexed as archived snapshots, not active input sources. Directory-level links do not prove that every citation supports every file in that directory. The next evidence-management improvement is to map each dataset record to exact source rows/pages/tables, license and access conditions rather than infer support from a neighboring register.

The current master record set contains 923 records: A=15, B=154, C=49, E=597, unclassified=101, and project controls=7; it emits no D quality labels. E denotes an unverified or placeholder record, not an evidence upgrade. Fourteen frontend-preview references remain explicitly non-backend-authoritative; unsupported preview values are labeled E. The 55 TEA cost records are graded in `Greenhub/data/tea/tea_cost_quality_review.json`: 33 directly sourced benchmarks are B, 18 scaled/combined engineering values remain C only where literature-linked, and four unsupported/user-provided amounts are E. The separate user-supplied biomethane price remains E; its value and user provenance are unchanged. B describes source evidence, not project transferability; the cost register retains source status, applicability, confidence and cost-boundary limitations. The 23 storage reaction inputs are DOI-linked C assumptions in the user-facing catalog; their citations do not validate the numerical kinetics for roadside grass. D4/D5 labels elsewhere describe evidence/readiness gates, not data quality classes.

### 2026-11-11 food-composition and bioprocess evidence audit

The normalized input CSVs and JSON snapshots were rebuilt after correcting the cassava-press source identity and separating evidence quality from transferability. A scan of quality/evidence-class fields in `Greenhub/data/**/*.csv` and normalized JSON found zero exact D grades. The Phase 3–7 reuse catalog now reports 528 E placeholders and 10 B values, zero D; the 528 E records remain unresolved and must not be described as validated. The catalog builder maps legacy D/E input labels to E without changing numeric values or runtime behavior. D remains in shared schemas solely for legacy read compatibility, and D1–D5 remains a separate maturity vocabulary.

For food composition, the UI defaults retain their numeric values and override precedence. The three cultivated-ryegrass cell-wall values are correctly C for the GreenHub roadside profile, while the source observations remain B. Czubaszek et al. (2023), DOI `10.3390/en16114488`, Table 5, is indexed as 12 B/reference-only seasonal roadside/median-grass measurements. Crude fiber overlaps cell-wall fractions; hemicellulose and cellulose are assay-derived differences; only analytical triplicates are stated, not independent site replication. The reference data are therefore not summed into or activated in the UI composition.

For Phase 3–7, the source corrections make literature measurements B only where their identities and DOI/table locations are verified; unsupported target-specific values remain blank/E. In particular, the corrected cassava press records and alfalfa clarification observations are reference-only comparators, not grass recovery coefficients. No route equation, API contract, model default value, or process balance changed. The data still require matched GreenHub feed/juice/cake composition and flow, protein-form and nutrient-speciation assays, route-specific reagent/energy use, post-protein residual BMP/reactor data, gas slip and N/P/K product analyses.

The active starch input was updated on 2026-11-11 from the weak secondary-source proxy to a traceable primary-study comparator: Gierus et al. (2024, DOI [`10.3390/agronomy14010168`](https://doi.org/10.3390/agronomy14010168)), Table 2, reports mean 34 g/kg DM across n=100 cultivated perennial-ryegrass NIRS calibration/validation samples (range 1–169; R²=0.77; SEC=1.45; SEV=2.23 g/kg DM). The GreenHub UI profile converts 34/1000 × the separate VARTA measured DM fraction 0.143 to 0.004862 kg/kg wet feed. The applied value is class C because the cultivated ryegrass accessions are not the GreenHub roadside species mixture or VARTA batch; the source row remains B and `reference_only`. The range is not a probability distribution, transfer uncertainty is unquantified, and this is not a GreenHub starch assay. The prior Guțu et al. (2025) secondary-source candidate remains in the proxy inventory for traceability. The new source CSV and JSON sidecar record the exact table, geography, method, uncertainty, rights, and conversion; the local source register, dataset manifest, global source index, FAIR catalog and tests were refreshed.

Olszewska (2021; DOI `10.3390/agronomy11030468`) is now staged as 36 reference-only group summaries for water-soluble carbohydrates, crude protein, and the WSC:CP ratio across cultivar, nitrogen rate, harvest time, and cut. These are direct B-tier measurements from cultivated perennial ryegrass, not GreenHub roadside grass; the tables provide marginal means, not joint-factor records or uncertainty spreads. They may inform a future ryegrass-specific seasonal adapter, but no values were applied to the current UI profile or process calculations. The UI's unresolved sugar species, true/soluble protein partition, nitrogen/phosphorus/potassium speciation, contamination fractions, and other M fallbacks remain unresolved where source evidence does not match.

The dynamic raw-press evidence report now exposes records `RAW_0001`–`RAW_0009` with the cited *Lolium perenne* study's DOI URL, Table 1 location, record identifier and source quality B. B here denotes source evidence quality; the report separately identifies transferability and warns that these lab-scale, fresh ryegrass results are not validated for roadside-grass industrial operation. This is not a change to the empirical baseline press defaults.

Catalog identifiers (`urn:greenhub:dataset:sha256:…`) are content-addressed repository identifiers, not globally registered persistent identifiers. There is currently no DOI for the combined GreenHub input collection. A DOI should be added only after depositing a versioned release in a repository such as Zenodo; until then, repository URLs, hashes, source DOIs and local record IDs provide traceability but not a minted global identifier.

## Regeneration and review

1. Add or update the authoritative source file and its record-level provenance first.
2. Keep values, bases, uncertainty, applicability, source location, retrieval date and quality distinct; never replace missing data by zero without an explicit assumption.
3. Rebuild the catalog and refresh the workbook catalog sheet.
4. Review changed hashes and unmatched sources. Re-run the input/override and reporting tests before release.
